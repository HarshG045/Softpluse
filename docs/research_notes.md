# SoftwarePulse Research Notes & Positioning

## 1. Differentiating SoftwarePulse from AI Coding Assistants

| Characteristic | AI Coding Assistants (e.g. Copilot) | SoftwarePulse Platform |
| :--- | :--- | :--- |
| **Primary Scope** | Line/block/function code generation | Repository-level software evolution intelligence |
| **Analysis Basis** | Prompt context & local file buffers | Full Git commit history, AST metrics & dependency graph |
| **Objective** | Real-time code synthesis & completion | Component risk prediction & architecture degradation analysis |
| **Exploration** | Natural language chat / prompting | Quantitative What-If counterfactual change simulation |

## 2. Scientific Limitations & Boundaries

1. **Risk Prediction vs Defect Certainty**: Risk prediction indicates estimated probability of change-proneness / defect association; it is not a formal mathematical proof of a defect.
2. **Commit Heuristic Labels**: Keyword-based commit message analysis serves as an empirical heuristic and may contain noise.
3. **What-If Counterfactual Interpretation**: What-If simulation modifies the model's feature representation to estimate prediction shifts; it is a model-based sensitivity analysis rather than proven causal impact.
4. **Language Parsing**: The mid-semester version utilizes Python AST for parsing Python components.
