# SoftwarePulse Project Distribution Among Three Members

## Main Purpose of the Project

SoftwarePulse is an AI-based software risk prediction system. It analyzes a software repository and predicts which files or components may have higher future risk.

The system combines:

1. Static code information:
   - Lines of code
   - Functions
   - Classes
   - Methods
   - Imports
   - Cyclomatic complexity

2. Git history:
   - Number of commits
   - Code churn
   - Recent changes
   - Number of contributors
   - Bug-fix commits
   - Change frequency

3. Dependency information:
   - Dependencies
   - Dependents
   - In-degree
   - Out-degree
   - Total degree
   - Centrality
   - Circular dependencies

4. Machine learning:
   - Predicts component risk
   - Assigns LOW, MEDIUM, or HIGH risk
   - Compares different feature groups

5. Dashboard features:
   - Risk charts
   - Repository evolution
   - Prediction explanations
   - What-if simulations

The main research question is:

> Does using Git history and dependency information improve software risk prediction compared with using only static code metrics?

## Complete System Flow

```text
Repository
    -> Repository loading
    -> Git history extraction
    -> AST code analysis
    -> Dependency graph creation
    -> Feature engineering
    -> Temporal dataset creation
    -> Machine learning training
    -> Risk prediction
    -> Explainability and simulation
    -> Streamlit dashboard
```

## Repository Loading Functions

- `RepositoryLoader.is_github_url()`
  - Checks whether the input is a remote GitHub, GitLab, or Bitbucket URL.

- `RepositoryLoader.clone_remote_repo()`
  - Clones a remote repository into the local data directory.

- `RepositoryLoader.load_repository()`
  - Loads either a local or remote repository and returns its path and metadata.

- `RepositoryLoader.extract_metadata()`
  - Calculates repository name, file count, languages, branch name, commit count, contributor count, and commit dates.

## Git Analysis Functions

- `GitLoader.is_git_repo()`
  - Checks whether the selected folder is a Git repository.

- `GitLoader.get_commit_history()`
  - Extracts commit hashes, authors, dates, messages, changed files, insertions, deletions, and bug-fix status.

- `GitLoader.get_commit_detail()`
  - Returns detailed information about one commit and its file changes.

- `GitLoader.get_contributor_stats()`
  - Calculates contributor activity.

- `GitLoader.get_component_git_history()`
  - Returns all commits related to a specific file.

- `GitLoader.get_branches()`
  - Returns the current branch and all branches.

- `GitLoader.compare_branches()`
  - Compares branches using commits, changed files, insertions, and deletions.

- `GitLoader.get_working_tree_diff()`
  - Returns uncommitted file changes.

## Static Code Analysis Functions

- `CodeAnalyzer.analyze_file()`
  - Uses Python AST to calculate lines of code, functions, classes, methods, imports, branches, complexity, imported modules, and syntax errors.

- `CodeAnalyzer.analyze_repository()`
  - Scans and analyzes all Python files in the repository.

- `CyclomaticComplexityVisitor`
  - Calculates complexity from if statements, loops, exception handlers, Boolean expressions, conditional expressions, and pattern matching.

## Git Evolution Function

- `GitAnalyzer.analyze_components()`

This function calculates:

- Commit count
- Recent commit count
- Total churn
- Recent churn
- Number of authors
- Change frequency
- Time since last change
- Bug-fix commit count

## Dependency Graph Functions

- `DependencyAnalyzer.build_graph()`
  - Creates a NetworkX directed graph using Python imports.

- `DependencyGraph.add_component()`
  - Adds a file as a graph node.

- `DependencyGraph.add_dependency()`
  - Adds a dependency edge.

- `DependencyGraph.remove_dependency()`
  - Removes an existing dependency edge.

- `DependencyGraph.get_metrics_for_all()`
  - Calculates dependency count, dependent count, in-degree, out-degree, total degree, and centrality.

- `DependencyGraph.get_neighborhood()`
  - Returns neighboring components for a selected file.

- `DependencyGraph.detect_cycles()`
  - Finds circular dependencies.

- `DependencyGraph.get_architectural_hotspots()`
  - Finds highly connected components.

- `DependencyGraph.get_package_clusters()`
  - Groups components by package and calculates package instability.

- `DependencyGraph.clone()`
  - Creates a copy of the graph for simulation.

A dependency edge is represented as:

```text
source file -> target file
```

This means that the source file imports or depends on the target file.

## Historical Analysis

## Dataset Creation Functions

- `LabelGenerator.generate_labels()`
  - Creates risk labels based on future bug-fix commits.

- `LabelGenerator._generate_churn_proxy()`
  - Creates proxy labels using future code churn when bug-fix commits are unavailable.

- `TemporalSplitter.split_by_time_cutoff()`
  - Creates a chronological training and testing split.

- `DatasetBuilder.build_dataset()`
  - Controls the complete dataset-building process.

The dataset builder extracts historical features, generates labels, separates training and testing data, prevents future data leakage, and returns the final `BuiltDataset` object.

- Handle Python files with syntax errors.

- Keep feature names synchronized with `feature_schema.py`.
- Test repositories with circular dependencies.
- Test empty and small repositories.

## Model Training Functions

- `ModelTrainer.train_model()`
  - Trains the selected machine learning model.

- `ClassifierAlgorithm`
  - Defines the supported algorithms.

- `TrainedModelBundle`
  - Stores the model name, algorithm, feature set, feature names, trained pipeline, training date, training samples, positive samples, and negative samples.

Supported models:

- Random Forest
- Logistic Regression

Supported feature configurations:

1. Static features only
2. Static plus evolution features
3. Static plus evolution plus dependency features

## Prediction Functions

- `RiskPredictor.classify_risk()`
  - Converts probability into LOW, MEDIUM, or HIGH.

- `RiskPredictor.predict()`
  - Selects model features, calculates probability, converts probability to a percentage, assigns a category, creates component profiles, and sorts components by risk.

- `ComponentRiskProfile.to_dict()`
  - Converts a component risk profile into a dictionary.

## Model Evaluation Functions

- `ModelEvaluator.evaluate_bundle()`
  - Calculates accuracy, precision, recall, F1-score, ROC-AUC, confusion matrix, true positives, false positives, true negatives, and false negatives.

- `ModelEvaluator.run_comparative_experiment()`
  - Compares three research configurations.

Model A: Static features only.

Model B: Static plus evolution features.

Model C: Static plus evolution plus dependency features.

The purpose is to determine whether Git history and dependency information improve prediction performance.

## Explainability Functions

- `ModelExplainer._compute_global_importances()`
  - Calculates the importance of each feature in the trained model.

- `ModelExplainer.get_global_importance_df()`
  - Returns feature importance values in a DataFrame.

- `ModelExplainer.explain_component()`
  - Explains why a component received its risk score.

The explanation contains:

- Top contributing features
- Feature values
- Importance weights
- Impact level
- Human-readable explanation

## What-If Simulation Functions

- `WhatIfEngine.simulate_change()`
  - Simulates a hypothetical change and calculates the new risk.

- `SimulationChangeType`
  - Defines the supported simulation types.

Supported changes:

- Add dependency
- Remove dependency
- Increase complexity
- Decrease complexity
- Increase churn
- Increase change frequency

The simulation process is:

1. Clone the original dependency graph.
2. Modify the selected dependency or feature.
3. Recalculate graph metrics if required.
4. Create a modified feature vector.
5. Run the trained model again.
6. Compare original risk with simulated risk.
7. Return the final `SimulationResult`.

## Change Impact Analysis

The change analyzer identifies components affected by repository changes and connects them with:

- Changed files
- Dependency relationships
- Current risk profiles
- Risk changes

- Use the same model for original and simulated predictions.
- Explain that predictions are estimates and not proof that a bug exists.
- Explain that what-if simulation is not causal proof.
